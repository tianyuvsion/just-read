两种检查，两个问题

“引用存在”与“支持结论”分开

location_check

原文里是否真的有这段话？

程序检查来源修订、位置和摘录匹配。规范化文本时保留与原文位置的映射。

support_check

这段话是否支持这个结论？

语义检查评估支持、矛盾、条件和证据不足，并用人工参考样本校准漏检。

不能压成一个 verified 字段。
作者说过某句话、来源可信、结论适用于当前问题，是不同判断。

接口与步骤共享同一份契约

接口输入 / 输出必须成立的规则
POST /runs问题、材料引用、client_request_id
返回 run_id / revision / deadline_at		幂等创建；关闭页面不终止生产。
GET /runs/{id}/events已保存的阶段和错误事件SSE 用事件序号续传，不用重连触发新任务。
POST /artifacts/{id}/revisionsbase_revision ＋ 修改内容创建新修订；冲突返回 409 并保留修改。
POST /runs/{id}/rerun新输入引用，返回新 run_id旧运行可追溯，但无权写回当前新稿。
POST /reports/{version}/build-export固定清单，返回 export_id不临时拼装 latest；最终文件通过离线检查后才可下载。
执行状态与内容状态如何区分

execution_status

queued / running / paused / succeeded / failed / needs_input

描述步骤是否运行完成。needs_input 只处理确实需要用户独有信息的情况。

result_status

ready / partial / not_applicable / blocked

描述结果是否足够使用。整份可交付状态由所有必需项和检查记录共同计算。

04

三类表达，分别用确定的技术实现

受控生成

先让模型说明“表达什么”，再由代码决定“怎样呈现”。表达规格共享 ResearchIR 的证据与数据，不各自生成一套事实。

FIXED COMPONENTS / SEMANTIC SPECS

图解是论证的表达层

正文按固定阅读块组织。数据图绑定 Dataset 或 Calculation；流程与关系图先保留业务语义，再计算布局。

ResearchIR→VisualSpec→固定组件
正文：带主张引用的连续阅读块

NarrativeBlock 记录 semantic_role、claim_refs、evidence_refs 和默认可见性。核心结论和限制直接呈现，术语与来源按需展开。

数据图：ECharts ＋ SVGRenderer

ChartSpec 指定图型、数据引用、维度映射、单位、刻度与精度。展示数值来自锁定的数据集，缺失值保持缺失。

关系图：Dagre 布局 ＋ 自有 SVG

DiagramSpec 的边区分 sequence、association、dependency、causal_claim。布局只改变坐标，不能改变业务关系。因果主张需关联证据。

写作遇到新的事实需求怎么办？
返回研究步骤补证据，生成新的 IR 修订，再重新派生相关正文与图解。

FORMULA REGISTRY / SHARED ENGINE

模型选公式，计算交给程序

首版只注册实际案例需要的公式。TypeScript ＋ decimal.js 实现共享计算包，Python worker 通过固定 Node 接口调用；需要离线情景计算时编入同一版本。

Dataset→口径检查→公式执行→Calculation
  • 原值以十进制字符串保存；记录币种、单位、期间、主体、指标定义、合并范围和实际 / 预测类型。
  • 缺数、零分母、口径冲突均返回不可计算状态，缺失不能补零。
  • 内部计算精度独立配置；最终用 toDecimalPlaces 指定小数位与舍入方式。保存公式版本、输入引用和结果，模型读取结果后形成解释。
若提供离线滑杆：调整的是独立假设情景，原始事实和报告结论保持不变。服务端与阅读器用同一组固定样例核对结果。

{
  "formula_id": "gross_margin",
  "formula_version": 1,
  "inputs": {
    "revenue": "dataset/revenue@r3",
    "cost_of_revenue": "dataset/cost@r3"
  },

可靠执行的四个机制

领取租约与执行令牌

数据库事务领取就绪步骤，写入 lease_expires_at 和递增 fencing_token，再释放事务调用模型。失联后可重新领取，过期令牌不能提交当前结果。

检查点与幂等接纳

每步记录 input_hash，输出保存为不可变产物。外部调用可能重复发生、重复计费；唯一约束和执行资格检查保证不重复发布。

状态事件与 SSE 回放

步骤状态和 run_events 在同一事务写入。SSE 按序号读取历史事件，刷新页面后恢复进度，不重新启动生产。

有限重试与修复路由

网络重试与内容返修分开计数，均使用原 deadline_at。AI 输出带 artifact_ref、json_pointer、code 的 issue，由程序选择重新获取、重算或重写指定块。

写回时检查修订与运行身份

COMPARE AND SWAP · 示意
UPDATE reports
SET current_revision = :new_revision
WHERE id = :report_id
  AND current_revision = :base_revision
  AND active_run_id = :expected_run_id;

-- 更新 0 行：拒绝过期提交
-- 写入还需校验有效执行令牌

人工修改创建新修订和新运行。暂停会撤销旧运行写入资格；不能取消的远程调用可以留档，但不能推进当前草稿。

首版重跑策略：允许整份重跑，只复用输入哈希一致且检查仍有效的产物。先保证一致性，再优化细粒度增量执行。

GLB 从内存加载

把自包含模型编码内嵌，解码为 ArrayBuffer，再交给加载器解析。

OFFLINE MODEL LOADING
const buffer = decodeBase64(asset.data);
const gltf = await loader.parseAsync(buffer, "");
viewer.attach(gltf.scene, modelPackage.parts);

decodeBase64 与 viewer.attach 是拟实现的项目函数。parseAsync 是 Three.js 提供的内存解析入口。

GLB 格式不保证自包含。检查外部纹理 / buffer URI；首版统一转换为无需外部压缩解码器的资产。若保留解码器，其 WASM 与 Worker 也须离线打包。

file:// 下的四个注意点

  1. 普通内联脚本：最终文件不保留外部 ESM import、动态拆包或相对路径 fetch。
  2. 资源完整：图片内嵌，使用系统或内嵌字体，必要运行资源不依赖 CDN。
  3. 体积与内存：base64 约增加三分之一体积，还会产生解码内存；用真实模型测上限。
  4. 绑定最终产物：离线检查记录 artifact_hash 和 manifest_hash，不能沿用在线预览的通过状态。

引用原文的外部链接可以联网打开；核心证据摘录与定位信息随文件保留。离线阅读不调用 AI。

单文件过大时，如何处理资源包

先测实际文件大小、加载时间和峰值内存，再决定边界。必要时可把编码资产拆为普通脚本加载的资源注册文件，解压后直接打开入口；不能简单改回 fetch('./model.glb')。单文件与资源包分别做 file:// 实测，不能要求读者启动本地服务器。

在模型调用、保存产物、提交状态之间中断 worker；同时提交人工新修订。

03

研究是否真的依靠自动取材
